**Spec:** each ticket's text and its "Decided (owner, 2026-11-26)" comment are the spec. Read them with `vaquero ticket show VAQ-N --agent claude`, read only. The owner approved writing this plan (2026-11-26), and reviews it before the run.

**Architecture:**

**Tech Stack:** as the repo. No new dependency.

- **Exactly one migration, `0013_history_profile.sql`,** written in Task 1:
  - `event_tickets (seq INTEGER NOT NULL REFERENCES events (seq), ticket_id TEXT NOT NULL, PRIMARY KEY (ticket_id, seq)) WITHOUT ROWID`;
  - a backfill from every existing event whose `payload.ticket_ids` is an array (decisions, tag events, `ticket.moved`);

  - `actor_avatars` (`actor_id` PK REFERENCES actors, `content_type`, `data` base64 TEXT, `etag`, `updated_at`), shaped like `project_icons`;

  Released fixtures must still migrate.
- `event_tickets` is derived data, written by core's `emit` in the same transaction as the event. It is not a second event. It isn't exported: import rebuilds it with the migration's backfill SQL, as `BackfillLinkTargets` does.
- Every new route, command and setting gets its help-article line. Copy follows copy-voice.
- **Gate,** each step separately by exit code: `make gen`, `make fmt`, `make vet`, `make lint`, `make test`, then `make ci`, plus `make e2e` for page changes.
- **Commits:** `{Area}: {summary} (VAQ-N)` with the Co-Authored-By line, staging only the changed paths.

## Rulings (controller, 2026-11-26; the owner can overrule)

- **P-R1 (VAQ-144, 147):** one lookup table instead of a JSON scan per kind.
  - `ListTicketEvents` becomes three indexed lookups: `events_ticket`, `events_link_to` and `event_tickets`.
  - The tag and move lookups from run N (`events_tag` through `json_each`, and the `up` CTE) are replaced, and their history tests must still pass.
  - A moved sub-ticket keeps its move line after it is detached or re-parented, because the move event lists it by id.
- **P-R2 (VAQ-145):** only a cancelled ancestor stops covering, as decided. A done epic keeps covering its open children. Done means the approved work finished, and a child left open is follow-up under the same plan.
- **P-R3 (VAQ-149):** the owner's actor keeps `name = "Owner"` as its identity (`EnsureOwner` finds it by name), and the profile sets `display_name`.
  - Every page, answer and history line shows `display_name` when it is set.
  - `--assignee` and the API's assignee accept either the name or the display name.
  - The CLI command is `vaquero me`, since `profile` already names connection profiles.
- **P-R4 (VAQ-148):** the file is `{data dir}/vaquero.env`.
  - **Its format:**
    - a line is `KEY=value`, with optional surrounding double quotes;
    - `#` starts a comment line, and blank lines are skipped;
    - only `VQ_` keys are allowed, and `VQ_DATA_DIR` is refused ("VQ_DATA_DIR can't be set in vaquero.env.");
    - an unknown `VQ_` key is a warning, not a refusal.
  - **It's refused when** its mode lets group or others read it: "vaquero.env can be read by other users; run chmod 600 {path}."
  - **The redaction function is `config.Redact(key, value string) string`:**
    - `VQ_S3_SECRET_ACCESS_KEY`: `••••••••` plus the last 4 characters, or `set` under 16 characters;
    - `VQ_S3_ACCESS_KEY_ID`: the first 4, `…`, and the last 4, or `set` under 12 characters;
    - any other key: unchanged.

## Review Focus

1. **The S3 secret:** it never appears whole anywhere a person or a log can see it. `TestRedactNeverLeaks` (Task 3) and `TestStorageSection` (Task 5).
2. **A brew service after a move:** it boots on the moved store with no hand editing, and a wrong or unreadable file stops it with a message naming the fix. `TestServeBootsFromEnvFile` and `TestEnvFileModeRefused` (Task 3).
3. **History:** every event that names a ticket shows on that ticket, still read by index. `TestTicketHistoryUsesIndexes` (Task 1).
4. **Deleting a backup** never touches anything outside the backups directory. `TestDeleteBackupRefusesOutsideNames` (Task 5).
5. **An agent** can't edit the owner's profile, and a cancelled epic stops covering its children. `TestProfileOwnerOnly` (Task 4) and `TestCancelledEpicStopsCovering` (Task 2).
