## Global Constraints

- CLAUDE.md hard invariants. The API is additive. Copy follows copy-voice. Every new command, route and shortcut needs its line in the help articles.
- **No migration.** Event payloads are JSON, so the new payload fields (VAQ-21) need none. If a migration seems needed, stop and report.
- CSP: no inline script and no `style=`. All behaviour goes in app.js. Templates use theme tokens only.
- **One new dependency is allowed, and only in Task 4:** `chromedp`, test-only, behind the `e2e` build tag (see the CLAUDE.md exception). No other new Go or npm dependency.
- CLAUDE.md and `.claude/rules/*` are edited only by the controller. Subagents write `claude-md-task-N.patch` in the run workspace.
- Never touch port 7878, the owner's data directory, or the owner's brew service. Manual checks use port 7881 with a temp `VQ_DATA_DIR`. Use headless Chrome (`--headless=new --window-size=W,H --screenshot`) for true widths.
- Gate, checking each step's exit code separately: `make gen`, `make fmt`, `make vet`, `make lint`, `make test`; then `make ci`. From Task 4 on, also `make e2e`. Commits are `{Area}: {summary} (VAQ-N)` with the Co-Authored-By line, and include only the paths changed.

## Review Focus

1. **History stays truthful** (VAQ-21, 32, 47):
   - old description text is stored and shown only for new events, and old events still render;
   - folded reorders never hide a status change;
   - link targets resolve by id, and an event without a `to_id` shows its recorded key;
   - every change is still exactly one event.
2. **Claims stay advisory** (VAQ-68): a warning never blocks an edit, in the API, the MCP answers or the web form.
3. **Search** (VAQ-40): the query rewrite keeps FTS5 syntax out (`MatchQuery`) and leaves nothing open to injection. Ranking and snippets are tested, and NFC is applied both when indexing and when querying (the triggers index the stored text, so normalise on write in core, or on both sides).
4. **Destructive actions** (VAQ-27, 17): the confirm dialog works without inline script, and without JavaScript the form still posts. Tag merge and delete are one event each and keep the ticket count right.
5. **Browser tests** (VAQ-33, 34, 131): tests wait for elements, never with sleeps; they skip cleanly without Chrome, and the gate workflow runs them.

## Rulings (controller, 2026-11-25; the owner can overrule)

- **R1 (VAQ-21):**
  - From now on, `ticket.updated` events that change the body carry `body_before` and `body_after`.
  - The ticket history shows "Show changes" (a `<details>`) with a line diff rendered server-side in Go, with no JS diff library. Keep it a simple LCS over lines; add no dependency.
  - Cap the stored text at 64 KiB per side, and say "too long to show" past it.
  - The activity page shows the sentence only.
- **R2 (VAQ-32):**
  - The activity page and the activity API leave out `ticket.reordered`.
  - The ticket history folds a run of consecutive reorders by the same actor, with no other event between them, into one line ("reordered 4 times").
  - The `/events/stream` sequence still advances.
- **R3 (VAQ-47):**
  - A link event's target is resolved at render time from `payload.to_id`: the current key, linked, or "a deleted ticket" when it's gone.
  - Events without a `to_id` keep the recorded key, unlinked.
  - Do the lookup in one batched read per page, not one per event.
- **R4 (VAQ-68):**
  - Write answers (the API and MCP) for a ticket claimed by someone other than the caller add `"warning": "Claimed by X until HH:MM."`, an additive field.
  - The web edit form shows a note when someone else holds the claim.
  - The agents article states the rule.
  - Bulk results carry the warning per item.
- **R5 (VAQ-40):** as the decision comment says, all five points.
  - Matching across the title, body and comments: a ticket matches when every term matches somewhere in that ticket.
  - Ranking: one merged list, ranked by the best bm25 per ticket, normalised per table, or by an explicit simple score. Document the choice in the code.
  - "showing 50 of N" needs a count.
- **R6 (VAQ-27):**
  - A `<dialog>` in the Shell, opened by app.js for forms marked `data-confirm="…"`. It covers comment delete, status delete, project archive, tag delete and tag merge.
  - Without JS, the form submits directly, as today.
  - Project delete keeps its typed-key check.
- **R7 (VAQ-17):**
  - A Tags section in project settings with rename, merge (rename onto an existing name, matched by `SameTag`) and delete.
  - Each is a core operation with one event: `tag.renamed`, `tag.merged`, `tag.deleted`.
  - Add API routes only if it's cheap and additive; they aren't required.
- **R8 (VAQ-109):** the four changes in the ticket.
  - Autocomplete is an htmx-driven `<datalist>` or a listbox fed by a small search route. It matches the number or the title, with the project prefix optional.
- **R9 (VAQ-129):** style the progress value with theme tokens through `::-webkit-progress-value` and `::-moz-progress-bar` in input.css, in light and dark.
- **R10 (VAQ-63, VAQ-106, VAQ-53):** as the decision comments say.
  - Help hits come from `internal/help`, matching titles, summaries and headings in memory. No FTS is needed.
- **R11 (VAQ-130):**
  - When the lock holder's pid isn't the service manager's pid for the label (`launchctl print gui/UID/LABEL` → `pid =`; `systemctl --user show -p MainPID`), `vaquero stop` stops the lock holder and says so, without touching the service. Use the same bounded, injectable probes as run J's batch A.
  - When the pids match, keep the refusal.
- **R12 (VAQ-33, 34, 131):** as the decision comments say.
  - VAQ-33 builds the harness first: package `internal/e2e`, or `e2e/` at the root, with the `//go:build e2e` tag.
  - Add a `make e2e` target, and add `make e2e` to the gate workflow, pinned.
