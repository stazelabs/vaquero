## Review Focus

1. **A ticket moved to another project** (VAQ-18):
   - its old key resolves everywhere a key is accepted (URL, API, CLI, MCP, bulk), redirecting or answering for the new key;
   - its links, comments, attachments, plan, decisions and approvals stay attached;
   - readiness doesn't silently carry an approval across: the moved ticket's parent changes, so L-R11 applies.
2. **Renaming or merging a tag** (VAQ-134) shows a line in each affected ticket's history. `TestTicketHistoryUsesIndexes` still holds with the third lookup.
3. **Moving attachments** (VAQ-7) never leaves the instance pointing at a backend that lacks a file. An interrupted move resumes, and `--delete-old` deletes only after every file is verified.
4. **Export never writes an archive this version refuses to import** (VAQ-132).
5. **The Linear CSV import** (VAQ-8) keeps team keys and issue numbers. It refuses a CSV whose columns it doesn't recognise, with a message naming the missing columns, and never guesses.

## Rulings (controller, 2026-11-26; the owner can overrule)

- **N-R1 (VAQ-18 and readiness):** a moved ticket's approvals stay in history but no longer make it ready. Its project, key and parent changed, so it needs re-approval in the new project. Its plan moves with it.
- **N-R2 (VAQ-18 and decisions):** open decisions naming a moved ticket stay in the old project and say so in their history. Moving is refused while the ticket is in an open run (part 3; no runs exist yet, so this only adds a check).
- **N-R3 (VAQ-119):** project links show on the projects page cards and list (from run M) and on the project settings page.
- **N-R4 (VAQ-8):**
  - Supported columns come from Linear's public export documentation, cited in the code and the help.
  - A required column that's missing refuses the import, naming each one.
  - Unknown extra columns are ignored, and the summary lists them.
  - If the documentation doesn't settle the column names, stop: VAQ-8 goes to Needs decision, with the open question written on it.

### Task 4: Moving attachments, and the export size check (VAQ-7, VAQ-132)

`vaquero attachments move --to dir|s3 [--delete-old]` is offline and holds the maintenance lock. It copies each file and verifies its size and checksum, then switches `blob_store` and `blob_location` in one transaction. It records a pending file, resumes after an interruption, and deletes old copies only with `--delete-old` once every file is verified (Review Focus 3).

Export refuses before writing when export.json would pass `archive.MaxDocument`, and HEAD `/api/v1/export` checks the same (Review Focus 4).

- [ ] Test-first. Commit, then gate.

### Task 5: Linear CSV import (VAQ-8)

`vaquero import linear FILE.csv [--project KEY]` runs on the empty-instance rules or into a new project. It works out which columns are supported from Linear's documentation (N-R4). It keeps team keys and issue numbers, maps states to statuses by category, and maps labels to tags. It notes in its summary that comments, relations and attachments aren't in the CSV. Naming the source product is allowed in this one place.

- [ ] Test-first against a sample CSV built from the documented columns. Commit, then gate.
