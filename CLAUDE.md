# CLAUDE.md

Guidance for working in this repo. Keep it short and current: edit it when an invariant or a product decision changes. Feature detail goes in the package's doc comment, not here.

## Summary

Vaquero is an agent-native, local-first, lightweight ticket tracker with coordination primitives for agents. One Go binary, one SQLite file. Local mode (one person, loopback) now; hosted mode (sign-in, cloud) from Phase 4. Design: docs/superpowers/specs/2026-11-18-vaquero-design.md. Plans: docs/superpowers/plans/ (Phase 0 foundation, Phase 1a core tracker, Phase 1b board, Phase 2a API and CLI, icons and help, Phase 2b agents, Phase 3a releases and upgrades). Releasing: docs/RELEASING.md. Work list: docs/BACKLOG.md (no outside tracker; it moves into vaquero itself in Phase 3). Add deferred work and open questions there, and tick lines when they ship. Infrastructure is ported from the sibling projects startcase and healthcheck-email (read-only); the porting reference is /Users/cstaszak/Stazelabs/projects/startcase/docs/superpowers/plans/2026-11-17-porting-map.md.

## Commands

    make tools     # one-time
    make gen       # templ + sqlc + tailwind (generated files are committed)
    make dev       # air hot reload on 127.0.0.1:7879 (7878 is a real vaquero's port)
    make test

Run `make` with no target to list every target; give each new target a `## description`.

Gate before every commit that touches Go, SQL, templ or CSS: `make gen && make fmt && make vet && make lint && make test`. Before gen inputs exist the gate is `make fmt vet lint test`. `make ci` adds `cover-check` (floors in coverage-floors.txt).

## Package map

- `vaquero` (the module root, `legal.go`): `License()` and `Notice()`, the repo's LICENSE and NOTICE embedded for the licences page.
- `internal/legal`: `ThirdParty()` reads the generated `third_party.json` (every module linked into `cmd/vaquero` for linux/amd64 and darwin/arm64, the Go standard library, and htmx, SortableJS and Tailwind CSS, whose licence texts live in `internal/legal/vendor/`). `go run ./scripts/notices` writes it; `make gen` runs that. `TestThirdPartyCoversEveryLinkedModule` fails when a dependency changes without regenerating.
- `cmd/vaquero`: the binary; `cli.go` and `cli_cmds.go` are the CLI (`projects`, `project`, `tickets`, `ticket`, `comment`, `link`, `unlink`, `search`, `activity`, `ready`, `claim`, `heartbeat`, `release`, `attach` / `attachments` / `detach` (`cli_attach.go`: files checked before any upload, 10 MB, `-` needs `--name`), `token`, `profile`, `docs` (prints help articles, no server), `stop` and `backup list|restore` (`local_cmds.go`: no server; restore needs it stopped and snapshots the current database first, or moves it aside when it can't be copied; `stopLocal` SIGTERMs the lock holder and waits; both defer to `brew services` when its unit exists), `mcp` (`mcp.go`: a stdio MCP server bridging each JSON-RPC line to `/mcp`; stdout carries only JSON-RPC); flags may follow positional arguments, and everything after `--` is positional; every command takes `--profile`, `--agent` (or `VAQUERO_AGENT`) and `--json`; exit 0 ok, 1 failure, 2 usage, 3 conflict), a client of `/api/v1` that starts the local server when it isn't running, and restarts it when it runs an older release than the CLI (after `brew upgrade`; dev builds on either side are left alone); under `brew services` every start waits for the service manager first (`startLocal`); `serve` also holds the data-directory lock and keeps a live owner token in `{data dir}/token` (`ensureLocalToken`). The rest of this entry: `run(args, stdout, stderr) int` dispatches the subcommands (`serve`, `version`, `help`); `serve.go` has `serve(ctx, cfg, logger)` (binds the address first, then creates the 0700 data dir, opens the DB, snapshots it into `backups/` when migrations are pending (refusing to migrate if the snapshot fails), migrates, ensures the `instance_id` setting (minted once) and the blob backend lock (`checkBlobBackend` refuses a `VQ_BLOB_STORE` that differs from the recorded `blob_store` while attachments exist: "Attachments are stored in {old}; VQ_BLOB_STORE is {new}. Set it back to {old}."), opens the blob store, builds `core` and the owner actor, starts the sweep, serves, stops the sweep and drains 30 s on cancel, checkpoints the WAL); `main.go` has `openDB` and `newLogger`.
- `internal/version`: `Version`, `Commit`, `BuildDate` stamped via `-ldflags -X`; `Line()`.
- `internal/config`: `Load()`/`FromEnv(get)` read `VQ_MODE`, `VQ_ADDR`, `VQ_DATA_DIR`, `VQ_LOG_FORMAT`, `VQ_LOG_LEVEL`, `VQ_BLOB_STORE` (`sqlite` default, `dir` or `s3`), `VQ_BLOB_DIR` (default `{data dir}/attachments`) and `VQ_S3_ENDPOINT`, `VQ_S3_BUCKET`, `VQ_S3_ACCESS_KEY_ID`, `VQ_S3_SECRET_ACCESS_KEY`, `VQ_S3_REGION` (default `auto`; the first four are required for `s3`, every missing one named; the secret is never logged) into one flat `Config`; local mode refuses a non-loopback address; hosted mode is refused for now; `DefaultDataDir(goos, get)`; `AllowedHosts()`.
- `internal/blobs`: attachment bytes behind `Store` (`Put`, `Get`, `Delete`, `List`): `NewSQLite` (the `blobs` table, default), `NewDir`, `NewS3` (minio); `Open(cfg, w, r, now)` picks one from `Config`. Keys are `attachments/{instance}/{attachment id}`, lower case (`ValidKey`). `blobtest.Run` is the conformance suite. `blobs` is written only through the store, like `mcp_calls`.
- `internal/apitoken`: `Mint` ("vq_" + 32 random bytes, base64url), `Valid`, `Parse` (the Bearer header), `Prefix`, `Hash` (SHA-256; only the hash and prefix are stored), `TouchEvery`.
- `internal/lockfile`: `Acquire(dir)` takes an exclusive flock on `{dir}/vaquero.lock`; a second server on the same data directory gets `ErrLocked` and the holder's pid. `Holder(dir)` only probes (never writes the pid).
- `internal/api`: the API's JSON types (`types.go`, with `Attachment`, `IsInlineType` and the Markdown reference of a file) and answers: `Encode`, `WriteJSON`, `Failure`/`WriteFailure` (`{"error": {code, message, fields?, current?}}`), `FromCore` (Invalid→422, ErrNotFound→404, *Conflict→409 with the current object), `Decode` (one object, unknown fields refused, size limit → 413).
- `internal/client`: the CLI's HTTP client (`Client.Do`, `Client.Upload` (multipart `file` part), `*Error`, `UpgradeNeeded` from `Vaquero-Min-Client`), profiles (`Config` in `{user config dir}/vaquero/config.json`, mode 0600; `Resolve`: flag, then `VAQUERO_PROFILE`, then the saved current one, then `local`), and `EnsureLocal` (starts `vaquero serve` in its own session when nothing listens, logs to `{data dir}/vaquero.log`, never hangs); `WaitUp` (waits for a service manager's restart); `Older`, `IsDev`, `ServerVersion` (the last answer's `Vaquero-Version`).
- `internal/idgen`: `New()` mints ULID primary keys.
- `internal/timefmt`: the only place instants are formatted for storage or display.
- `internal/db`: SQLite writer/reader pools (`Open`, `OpenReader`, `Checkpoint`), embedded goose migrations (`Migrate` refuses a database from a newer vaquero; `Newest`, `Version`, `MigrateTo`); `queries/` feeds sqlc into `db/gen`; `db/dbtest.New(t)` gives a migrated per-test database. `Snapshot`/`PruneBackups` (backup.go, ported from startcase without the sessions scrub) copy the database with `VACUUM INTO` after a free-space check; `0004_hard_delete.sql` removes hard-deleted tickets and comments from the search indexes; `0006_agents.sql` adds the claim columns on tickets (`claimed_by`, `claim_expires_at`, `claim_prev_status_id`), a trigger that ends a claim when its ticket reaches done or cancelled, and the `mcp_calls` log. Tables: `settings`; the tracker (`0002_tracker.sql`): `actors`, `projects`, `statuses`, `milestones`, `tickets`, `tags`, `ticket_tags`, `comments`, `ticket_links`, `events`; `0003_board.sql` adds `tickets.status_changed_at` and the FTS5 tables `tickets_fts` and `comments_fts` (external content, kept current by triggers; deleted comments leave the index). `SearchTickets` (search.go) is the one hand-written query, because sqlc can't read FTS5 tables; snippets mark hits with \x02 and \x03.
- `internal/core`: the only code that writes the tracker. `Core{DB, Now}`; each operation is one writer transaction that validates, writes and appends exactly one `events` row (a refused one writes nothing; a no-op update writes nothing). Errors: `*Invalid{Fields}` (form field → sentence-case message) and `ErrNotFound`. Operations: `EnsureOwner`; `CreateToken` / `RevokeToken` (token.created and token.revoked events); `CreateProject` (seeds six statuses) / `UpdateProject` / `SetProjectArchived` / `ChangeProjectKey` (the old key stops resolving and is free again) / `DeleteProject` (typed key confirms; removes the project's tickets, tags, comments, links from any project, history, milestones and statuses; one `project.deleted` event remains); `CreateStatus` / `RenameStatus` / `MoveStatus` / `DeleteStatus` (keeps one per category, refuses one in use); `CreateMilestone` / `UpdateMilestone` / `SetMilestoneClosed`; `CreateTicket` / `PatchTicket` (only the named fields change; with a version, a stale save is `*Conflict` with the current ticket) / `UpdateTicket` (a full patch, no version check) (tags created as needed; parent same project, no cycles; position spaced by 1024, end of column on status change); `AddComment` / `EditComment` / `DeleteComment` (author only, soft delete); `AddLink` / `RemoveLink` (blocks, relates, duplicates; any project; "blocks" loops, direct or through a chain, and two-way "duplicates" are refused); `EnsureAgent` (an agent actor by name, made on first use); `Claim` / `Heartbeat` / `Release` / `ExpireClaims` (claims.go: a claim assigns the ticket and moves backlog or todo to the first in-progress status, with a lease of 1 minute to 2 hours, default 15; one live claim per ticket; heartbeat extends it and writes no event, the one exception to the event rule; release keeps status and assignee; a lapse returns an in-progress ticket to its earlier status, unassigned); `MoveTicket` (a board drop: status and position between two neighbours, midpoint positions, the column renumbered when a gap falls under 1e-6; a status change records ticket.updated, a reorder ticket.reordered). Status changes set `status_changed_at`. `ParseTicketKey` ("vaq-012" → VAQ-12), `ResolveTicket`, `Categories`, `LinkKinds`, `EventKinds`, the `Ev*` kinds and their payloads (events.go). `TestEveryOperationEmitsOneEventOrNothing` covers every operation.
- `internal/board`: the board and list views: `ParseFilter`/`Filter` (mine, agents, tag, priority, milestone or "none", assignee; lives in the query string; `With` builds chip links), `Load` (active columns, backlog and cancelled rails, done columns limited to `DoneWindow` with an `Older` count, open-milestone progress, open tickets without a milestone), `LoadList` (every status, nothing hidden). A card is `Ready` when it is a todo, unassigned, unclaimed, has no open blocker and no open sub-ticket; cards carry their claim (`ClaimedBy`, `ClaimExpiresAt`).
- `internal/sweep`: `Sweeper` runs every 30 s while serving: `core.ExpireClaims`, then deletes `mcp_calls` older than 30 days, then (with `Blobs`, at most once per `OrphanAge`, 1 h) deletes objects under `attachments/{Instance}/` with no `attachments` row, older than `OrphanAge`, logging and skipping a key it cannot delete. `Start`/`Stop`/`Tick`.
- `internal/mcpserver`: `Handler` is `POST /mcp` (Streamable HTTP, stateless, JSON answers; batches, wrong content types and empty bodies refused in the API's envelope). Each of the 14 tools (`ToolNames`) is one `/api/v1` request served in-process by the API routes as the caller, so its answer is the REST body and its refusal the REST message; panics are recovered. `log.go` records every `tools/call` (tool, actor, token prefix, argument `Summary` with values cut to 80 characters, outcome, duration) through `CallLog`.
- `internal/search`: `MatchQuery` turns typed text into quoted prefix terms (at most 20; no FTS5 syntax survives), `Run` searches through the reader pool and splits snippets into marked `Part`s.
- `internal/help`: the in-app documentation. Embedded `articles/*.md` with front matter (`title`, `section`, `summary`, `order`) rendered by goldmark (raw HTML escaped, script links refused); `Sections()`, `Get(slug)`, `SectionOf`; each `Article` has `HTML`, `Headings` (its `##` headings, for the contents list) and `Markdown` (title and summary on top, for agents). Tests fail when an article links to a missing page or heading, or when a CLI command, shortcut or API route is undocumented.
- `internal/web/icons`: Lucide glyphs by purpose. `ui.json` names them; `go run ./internal/web/icons/gen` (`make icons`, part of `make gen`) writes `ui_gen.go` from the pinned `lucide-static`, keeping only drawing elements; `UI(name)`, `UINames()`.
- `internal/markdown`: `Render(src) template.HTML` for ticket bodies and comments: goldmark (GFM), raw HTML shown as escaped text, images as `<img>` only for `/attachments/` destinations with no `..` segment (any other image is a link), then bluemonday's user-content policy with nofollow links.
- `internal/web`: `NewRouter(handlers.Deps)` mounts every route (global middleware with chi `GetHead`, `/healthz`, `/static/*`, `/` projects, `/activity`, `/events/stream`, `/search`, `/help` and `/help/{slug}` (`.md` for markdown), `/projects/new`, `/p/{key}/...` including `/board` (the board fragment) and `/list`, `/t/{ticket}/...` including `POST /move`, `/admin`, `/admin/tokens`, `/admin/mcp`, `/api/v1` with its own chain: `APIHeaders`, `APIToken`, JSON 404/405, and `POST /mcp` behind the same chain; `mountAPI` adds the API routes, used both there and in-process by MCP); `static.go` serves the embedded tree.
- `internal/web/middleware`: `APIToken` (also maps `Vaquero-Agent` to an agent in local mode for the owner's token, and keeps the token prefix on the context), request id, recover, `HostCheck` (403 for any Host but localhost, 127.0.0.1, ::1), request log, security headers, CSP nonce, `CrossOrigin` (403 for cross-site posts), `BodyLimit` (1 MiB; `MaxUpload` for `IsUpload` routes (`/t/*/attachments` and `/api/v1/tickets/*/attachments`), with the API's 413 envelope), `CurrentPath`.
- `internal/web/flash`: one toast across a redirect in a 60-second `vq_flash` cookie (local mode has no sessions): `Put`, `Pop`, `WithCurrent`, `Current`.
- `internal/web/handlers`: `Deps` (Cfg, DB for /healthz only, R reader queries, RDB the reader pool for search, Core, Actor, Logger, Now, Shutdown closed when the server stops, StreamPoll, Touch and MCPCalls: the two writers outside core, for a token's last use and the MCP log, Blobs: the attachment byte store, and Instance, which names its keys) plus `render` (pops the toast), `serverError`, `redirectWithFlash`, `invalidOrError`. `projects.go` (list, new, settings: name, statuses, milestones, archive; ## Hard invariants

- Module `github.com/stazelabs/vaquero`; binary `vaquero`; `go 1.27.0`, `toolchain go1.27.3`; always `CGO_ENABLED=0`.
- Env prefix `VQ_`.
- Dependency versions match startcase's `go.mod`. No ORM, no cgo SQLite, no React, no validation library, no testify, no cobra.
- Licence Apache 2.0. Supported platforms for the local binary: macOS and Linux.
- `VQ_MODE=hosted` is refused at boot until Phase 4 adds sign-in.
- Local mode binds loopback only and rejects any request whose Host is not `localhost`, `127.0.0.1` or `::1`.
- IDs come only from `internal/idgen` (ULID). Instants are stored as text only through `internal/timefmt`.
- Writer pool has exactly one connection. Inside a transaction use `gen.New(tx)`, never `Deps.Q`. Reads on request paths use the reader (`Deps.R`).
- CSP allows no inline script and no `style=` attribute. All behaviour is in `internal/web/static/js/app.js`.
- Templates use only the theme tokens; no raw hex or oklch values in `.templ` files.
- Generated files (`*_templ.go`, `internal/db/gen`, `tailwind.css`) are committed; `make gen && git diff --exit-code` must be clean.
- Documentation lives in `internal/help/articles` and ships in the binary; a new command, shortcut or API route needs its article line (tests enforce it). Icons are Lucide through `internal/web/icons`, never hand-drawn SVG.
- Copy: the product is "Vaquero" in prose and `vaquero` as a command. Sentence case, no exclamation points. Documentation and UI never name competing products.
- Local-first: everything works offline with the defaults; network services are optional and used only when the operator configures them. No telemetry; Vaquero never downloads or checks for releases.
- Never add `push` or `pull_request` triggers to GitHub workflows.
- Commit messages: `{Area}: {summary}`.
- Only `internal/core` writes the tracker tables, and every successful change appends exactly one `events` row in the same transaction. Handlers read through `Deps.R` and write only through `Deps.Core`.
- Agents: in local mode a request with the owner's token and a `Vaquero-Agent` header acts as that agent; other tokens ignore it. A ticket has at most one live claim; claims lapse, they are never silently stolen. MCP tools are API requests, never their own reads or writes.
- Tickets carry a `version` that rises on every change to the ticket; a save sent with an older version is refused (409 in the API, a banner on the web edit form, exit 3 in the CLI). Updates change only the fields they name.
- API tokens are stored as SHA-256 hashes with a 9-character prefix and shown once. Every API refusal is the same 401; never log a token.
- Upgrades go through Homebrew (`brew upgrade vaquero`) or a release archive; Vaquero never downloads or checks for releases. Releases are built by goreleaser from the manual `release` workflow (`.goreleaser.yaml`, Homebrew formula in `stazelabs/homebrew-vaquero` with a `brew services` block). `VERSION` is the exact `v*` tag on HEAD, else `0.0.0-dev`.
- `testdata/upgrade/` holds a database from every release (`make fixture VERSION=X` before releasing); `TestFixturesMigrateToHead` migrates each to head and compares every value. Never edit, regenerate or delete a released version's fixture (an unreleased one is remade if a migration lands before its release; the release workflow checks the schema).
- One server per data directory (`vaquero.lock`). The local token lives in `{data dir}/token` (0600).
- Operator pages live under `/admin` inside `AdminShell` (home, API tokens, MCP activity).
- A project key can be changed in settings; the old key then stops resolving (ticket links, branch names and commit references using it break) and is free for another project. Ticket keys are `KEY-N`; URLs accept any case and leading zeros and redirect to the canonical form.
- Deleting a project, migrating on boot and restoring a backup each take a database snapshot first (`{data dir}/backups`, newest `appdb.BackupKeep` = 7 kept); if the snapshot fails, nothing changes.
- Every page's footer carries "© 2026 Purple Bongo, Inc. · A Stazelabs project", the running version and links to `/about/licenses`. The logo is the cowboy hat (`static/logo.svg`, also the favicon).
- Departures from the siblings are deliberate: `internal/core` owns every mutation; passwords and passkeys (Phase 4); the CLI is an HTTP client (Phase 2).

## Rejected

mattn/go-sqlite3 (cgo), ORMs, gin/echo/fiber, React/Vite, Redis, validation libraries, testify, cobra, telemetry, Docker as a runtime requirement for local use.
