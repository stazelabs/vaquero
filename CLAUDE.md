# CLAUDE.md

Guidance for working in this repo. Keep it short and current: edit it when an invariant or a product decision changes. Feature detail goes in the package's doc comment, not here.

## Summary

Vaquero is an agent-native, local-first, lightweight ticket tracker with coordination primitives for agents. One Go binary, one SQLite file. Local mode (one person, loopback) now; hosted mode (sign-in, cloud) from Phase 4. Design: docs/superpowers/specs/2026-11-18-vaquero-design.md. Plans: docs/superpowers/plans/ (Phase 0 foundation, Phase 1a core tracker, Phase 1b board). Work list: docs/BACKLOG.md (no outside tracker; it moves into vaquero itself in Phase 3). Add deferred work and open questions there, and tick lines when they ship. Infrastructure is ported from the sibling projects startcase and healthcheck-email (read-only); the porting reference is /Users/cstaszak/Stazelabs/projects/startcase/docs/superpowers/plans/2026-11-17-porting-map.md.

## Commands

    make tools     # one-time
    make gen       # templ + sqlc + tailwind (generated files are committed)
    make dev       # air hot reload on 127.0.0.1:7879 (7878 is a real vaquero's port)
    make test

Run `make` with no target to list every target; give each new target a `## description`.

Gate before every commit that touches Go, SQL, templ or CSS: `make gen && make fmt && make vet && make lint && make test`. Before gen inputs exist the gate is `make fmt vet lint test`. `make ci` adds `cover-check` (floors in coverage-floors.txt).

## Package map

- `vaquero` (the module root, `legal.go`): `License()` and `Notice()`, the repo's LICENSE and NOTICE embedded for the licences page.
- `internal/legal`: `ThirdParty()` reads the generated `third_party.json` (every module linked into `cmd/vaquero` for linux/amd64 and darwin/arm64, the Go standard library, and htmx, SortableJS and Tailwind CSS, whose licence texts live in `internal/legal/vendor/`). `go run ./scripts/notices` writes it; `make gen` runs that. `TestThirdPartyCoversEveryLinkedModule` fails when a dependency changes without regenerating.
- `cmd/vaquero`: the binary; `cli.go` and `cli_cmds.go` are the CLI (`projects`, `project`, `tickets`, `ticket`, `comment`, `link`, `unlink`, `search`, `activity`, `token`, `profile`; flags may follow positional arguments; every command takes `--profile` and `--json`; exit 0 ok, 1 failure, 2 usage, 3 conflict), a client of `/api/v1` that starts the local server when it isn't running; `serve` also holds the data-directory lock and keeps a live owner token in `{data dir}/token` (`ensureLocalToken`). The rest of this entry: `run(args, stdout, stderr) int` dispatches the subcommands (`serve`, `version`, `help`); `serve.go` has `serve(ctx, cfg, logger)` (binds the address first, then creates the 0700 data dir, opens and migrates the DB, builds `core` and the owner actor, serves, drains 30 s on cancel, checkpoints the WAL); `main.go` has `openDB` and `newLogger`.
- `internal/version`: `Version`, `Commit`, `BuildDate` stamped via `-ldflags -X`; `Line()`.
- `internal/config`: `Load()`/`FromEnv(get)` read `VQ_MODE`, `VQ_ADDR`, `VQ_DATA_DIR`, `VQ_LOG_FORMAT`, `VQ_LOG_LEVEL` into one flat `Config`; local mode refuses a non-loopback address; hosted mode is refused for now; `DefaultDataDir(goos, get)`; `AllowedHosts()`.
- `internal/apitoken`: `Mint` ("vq_" + 32 random bytes, base64url), `Valid`, `Parse` (the Bearer header), `Prefix`, `Hash` (SHA-256; only the hash and prefix are stored), `TouchEvery`.
- `internal/lockfile`: `Acquire(dir)` takes an exclusive flock on `{dir}/vaquero.lock`; a second server on the same data directory gets `ErrLocked` and the holder's pid.
- `internal/api`: the API's JSON types (`types.go`) and answers: `Encode`, `WriteJSON`, `Failure`/`WriteFailure` (`{"error": {code, message, fields?, current?}}`), `FromCore` (Invalid→422, ErrNotFound→404, *Conflict→409 with the current object), `Decode` (one object, unknown fields refused, size limit → 413).
- `internal/client`: the CLI's HTTP client (`Client.Do`, `*Error`, `UpgradeNeeded` from `Vaquero-Min-Client`), profiles (`Config` in `{user config dir}/vaquero/config.json`, mode 0600; `Resolve`: flag, then `VAQUERO_PROFILE`, then the saved current one, then `local`), and `EnsureLocal` (starts `vaquero serve` in its own session when nothing listens, logs to `{data dir}/vaquero.log`, never hangs).
- `internal/idgen`: `New()` mints ULID primary keys.
- `internal/timefmt`: the only place instants are formatted for storage or display.
- `internal/db`: SQLite writer/reader pools (`Open`, `OpenReader`, `Checkpoint`), embedded goose migrations (`Migrate` refuses a database from a newer vaquero; `Newest`, `Version`, `MigrateTo`); `queries/` feeds sqlc into `db/gen`; `db/dbtest.New(t)` gives a migrated per-test database. `Snapshot`/`PruneBackups` (backup.go, ported from startcase without the sessions scrub) copy the database with `VACUUM INTO` after a free-space check; `0004_hard_delete.sql` removes hard-deleted tickets and comments from the search indexes. Tables: `settings`; the tracker (`0002_tracker.sql`): `actors`, `projects`, `statuses`, `milestones`, `tickets`, `tags`, `ticket_tags`, `comments`, `ticket_links`, `events`; `0003_board.sql` adds `tickets.status_changed_at` and the FTS5 tables `tickets_fts` and `comments_fts` (external content, kept current by triggers; deleted comments leave the index). `SearchTickets` (search.go) is the one hand-written query, because sqlc can't read FTS5 tables; snippets mark hits with \x02 and \x03.
- `internal/core`: the only code that writes the tracker. `Core{DB, Now}`; each operation is one writer transaction that validates, writes and appends exactly one `events` row (a refused one writes nothing; a no-op update writes nothing). Errors: `*Invalid{Fields}` (form field → sentence-case message) and `ErrNotFound`. Operations: `EnsureOwner`; `CreateToken` / `RevokeToken` (token.created and token.revoked events); `CreateProject` (seeds six statuses) / `UpdateProject` / `SetProjectArchived` / `ChangeProjectKey` (the old key stops resolving and is free again) / `DeleteProject` (typed key confirms; removes the project's tickets, tags, comments, links from any project, history, milestones and statuses; one `project.deleted` event remains); `CreateStatus` / `RenameStatus` / `MoveStatus` / `DeleteStatus` (keeps one per category, refuses one in use); `CreateMilestone` / `UpdateMilestone` / `SetMilestoneClosed`; `CreateTicket` / `PatchTicket` (only the named fields change; with a version, a stale save is `*Conflict` with the current ticket) / `UpdateTicket` (a full patch, no version check) (tags created as needed; parent same project, no cycles; position spaced by 1024, end of column on status change); `AddComment` / `EditComment` / `DeleteComment` (author only, soft delete); `AddLink` / `RemoveLink` (blocks, relates, duplicates; any project; "blocks" loops, direct or through a chain, and two-way "duplicates" are refused); `MoveTicket` (a board drop: status and position between two neighbours, midpoint positions, the column renumbered when a gap falls under 1e-6; a status change records ticket.updated, a reorder ticket.reordered). Status changes set `status_changed_at`. `ParseTicketKey` ("vaq-012" → VAQ-12), `ResolveTicket`, `Categories`, `LinkKinds`, `EventKinds`, the `Ev*` kinds and their payloads (events.go). `TestEveryOperationEmitsOneEventOrNothing` covers every operation.
- `internal/board`: the board and list views: `ParseFilter`/`Filter` (mine, agents, tag, priority, milestone or "none", assignee; lives in the query string; `With` builds chip links), `Load` (active columns, backlog and cancelled rails, done columns limited to `DoneWindow` with an `Older` count, open-milestone progress, open tickets without a milestone), `LoadList` (every status, nothing hidden). A card is `Ready` when it is a todo, unassigned, has no open blocker and no open sub-ticket.
- `internal/search`: `MatchQuery` turns typed text into quoted prefix terms (at most 20; no FTS5 syntax survives), `Run` searches through the reader pool and splits snippets into marked `Part`s.
- `internal/markdown`: `Render(src) template.HTML` for ticket bodies and comments: goldmark (GFM), raw HTML shown as escaped text, then bluemonday's user-content policy with nofollow links.
- `internal/web`: `NewRouter(handlers.Deps)` mounts every route (global middleware with chi `GetHead`, `/healthz`, `/static/*`, `/` projects, `/activity`, `/events/stream`, `/search`, `/projects/new`, `/p/{key}/...` including `/board` (the board fragment) and `/list`, `/t/{ticket}/...` including `POST /move`, `/admin`, `/admin/tokens`, and `/api/v1` with its own chain: `APIHeaders`, `APIToken`, JSON 404/405); `static.go` serves the embedded tree.
- `internal/web/middleware`: request id, recover, `HostCheck` (403 for any Host but localhost, 127.0.0.1, ::1), request log, security headers, CSP nonce, `CrossOrigin` (403 for cross-site posts), `BodyLimit`, `CurrentPath`.
- `internal/web/flash`: one toast across a redirect in a 60-second `vq_flash` cookie (local mode has no sessions): `Put`, `Pop`, `WithCurrent`, `Current`.
- `internal/web/handlers`: `Deps` (Cfg, DB for /healthz only, R reader queries, RDB the reader pool for search, Core, Actor, Logger, Now, Shutdown closed when the server stops, StreamPoll) plus `render` (pops the toast), `serverError`, `redirectWithFlash`, `invalidOrError`. `projects.go` (list, new, settings: name, statuses, milestones, archive; `{key}` case redirect), `tickets.go` (new/edit form with the parent typed as a key, ticket page with sub-tickets, links, comments and history; `{ticket}` canonical redirect; comment and link actions), `activity.go` (newest 100 events), `board.go` (board page and fragment, list view, filter chips, `TicketMove`: an htmx drop gets the refreshed board fragment; a refused or stale drop answers `HX-Refresh` with an error toast queued), `stream.go` (`/events/stream`: server-sent `change` events when the newest event sequence rises, polled every `StreamPoll`, pings every 25 s, read and write deadlines cleared, ends on `Shutdown`), `search.go`, `about.go` (`/about/licenses`), `admin.go` (`/admin`, tokens page: a new token shows once, on the POST answer), `api.go`, `api_read.go`, `api_write.go`, `api_tokens.go` (the REST API; names for status, assignee and milestone are resolved per project; tickets by key), `misc.go`; `projects.go` also has `ProjectKeyChange` and `ProjectDelete` (snapshot to `Deps.BackupDir`, then delete). Each handler is `func(Deps) http.HandlerFunc`. `TestHandlersNeverWriteDirectly` holds the core-only rule.
- `internal/web/templates`: templ components: `Shell` (toast, nav, header search box, the keyboard shortcuts dialog, tagline footer), `BoardPage`/`BoardSection`/`ListPage` (`board.templ`; live parts carry `data-live` and `hx-trigger="vq:change"`; open rails carry `data-rail`), `SearchPage`, project pages (`projects.templ`), ticket form and page (`tickets.templ`), `ActivityPage` and `EventLine`; `TextInput`, `TextArea`, `Select`, `FieldError` (`components.templ`); `EventSentence` wording for every event kind (`activity.go`), `CategoryLabel`, `PriorityLabel` and options (`labels.go`); class recipes in `helpers.go`. Theme tokens only.
- `internal/web/static`: embedded `css` (input.css with the `prose-vq` markdown styles + generated tailwind.css), `js/app.js` (toast fade and close; Sortable on every `[data-board-column]` in pointer-fallback mode, posting drops with `htmx.ajax`; one `EventSource` per tab on `/events/stream` that triggers `vq:change` on every `[data-live]` part, closes while the tab is hidden and catches up when shown, and holds a board refresh while dragging; open rails and sideways scroll kept across board refreshes; keyboard shortcuts, which leave Enter to focused links and buttons), `vendor/htmx.min.js`, `vendor/sortable.min.js` (copied from starfish), `favicon.svg`; `URL(path)` adds a content hash.
- `internal/web/webtest`: `New(t)` boots the real router in local mode on a test database with a fixed clock, core and the owner (`Deps.Core`, `Deps.Actor` to arrange state); `Client` (cookie jar; `Get`, `Head`, `GetWithHost`, `Post`, `PostHX`, `PostCrossSite`, `Follow`; never follows redirects itself); `Env.Shutdown()` ends open streams (cleanup calls it before closing the server); streams poll every 20 ms.

Agent rules for each area are in `.claude/rules/` (database, handlers, security, ui-theming, copy-voice).

## Hard invariants

- Module `github.com/stazelabs/vaquero`; binary `vaquero`; `go 1.27.0`, `toolchain go1.27.3`; always `CGO_ENABLED=0`.
- Env prefix `VQ_`.
- Dependency versions match startcase's `go.mod`. No ORM, no cgo SQLite, no React, no validation library, no testify, no cobra.
- Licence Apache 2.0. Supported platforms for the local binary: macOS and Linux.
- `VQ_MODE=hosted` is refused at boot until Phase 4 adds sign-in.
- Local mode binds loopback only and rejects any request whose Host is not `localhost`, `127.0.0.1` or `::1`.
- IDs come only from `internal/idgen` (ULID). Instants are stored as text only through `internal/timefmt`.
- Writer pool has exactly one connection. Inside a transaction use `gen.New(tx)`, never `Deps.Q`. Reads on request paths use the reader (`Deps.R`).
- CSP allows no inline script and no `style=` attribute. All behaviour is in `internal/web/static/js/app.js`.
- Templates use only the theme tokens; no raw hex or oklch values in `.templ` files.
- Generated files (`*_templ.go`, `internal/db/gen`, `tailwind.css`) are committed; `make gen && git diff --exit-code` must be clean.
- Copy: the product is "Vaquero" in prose and `vaquero` as a command. Sentence case, no exclamation points. Documentation and UI never name competing products.
- No telemetry, no outbound network calls.
- Never add `push` or `pull_request` triggers to GitHub workflows.
- Commit messages: `{Area}: {summary}`.
- Only `internal/core` writes the tracker tables, and every successful change appends exactly one `events` row in the same transaction. Handlers read through `Deps.R` and write only through `Deps.Core`.
- Tickets carry a `version` that rises on every change to the ticket; a save sent with an older version is refused (409 in the API, a banner on the web edit form, exit 3 in the CLI). Updates change only the fields they name.
- API tokens are stored as SHA-256 hashes with a 9-character prefix and shown once. Every API refusal is the same 401; never log a token.
- One server per data directory (`vaquero.lock`). The local token lives in `{data dir}/token` (0600).
- Operator pages live under `/admin` inside `AdminShell` (home, API tokens; MCP activity arrives in Phase 2b).
- A project key can be changed in settings; the old key then stops resolving (ticket links, branch names and commit references using it break) and is free for another project. Ticket keys are `KEY-N`; URLs accept any case and leading zeros and redirect to the canonical form.
- Deleting a project takes a database snapshot first (`{data dir}/backups`, newest 7 kept); if the snapshot fails, nothing is deleted.
- Every page's footer carries "© 2026 Purple Bongo, Inc. · A Stazelabs project", the running version and links to `/about/licenses`. The logo is the cowboy hat (`static/logo.svg`, also the favicon).
- Departures from the siblings are deliberate: `internal/core` owns every mutation; passwords and passkeys (Phase 4); the CLI is an HTTP client (Phase 2).

## Rejected

mattn/go-sqlite3 (cgo), ORMs, gin/echo/fiber, React/Vite, Redis, validation libraries, testify, cobra, telemetry, Docker as a runtime requirement for local use.
